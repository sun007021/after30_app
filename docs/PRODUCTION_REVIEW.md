# 프로덕션 심사 제출 자료

식후 30분(After30) — 사용자 테스트 결과 및 조치 내역

이 문서는 Google Play 프로덕션 액세스 신청 시 요구되는 세 가지 질문에 대한 답변입니다.
① 테스트를 어떻게 진행했는가 ② 어떤 피드백·문제가 나왔는가 ③ 그 결과 앱을 어떻게 바꿨는가

## 2. 테스트 진행 방식

실제 운영 서버(`https://api.pysun.kr`)에 이메일로 직접 가입해, 신규 사용자가 앱을 처음 쓰는 순서 그대로 기능을 사용하며 점검했습니다. 코드 리뷰가 아니라 **사용자가 겪는 증상** 기준으로 확인했습니다.

- **범위** — 회원가입·로그인, 약 등록·수정·삭제, 알람 수신과 복용 기록, 캘린더 조회, 가족 그룹 생성·초대·수락, 마이페이지 설정
- **방법** — 앱 화면 흐름을 따라가며 각 단계에서 실제 API를 호출하고, 응답과 화면 상태가 일치하는지 대조했습니다. 네트워크 단절, 잘못된 입력, 앱 재시작, 로그아웃 후 재로그인 같은 비정상 경로를 함께 확인했습니다.
- **테스트 데이터** — 테스트용 계정 4개, 복약 스케줄 6건, 가족 그룹 2개를 생성했으며 점검 후 **전량 삭제**했습니다.
- **결과** — 결함 30건 발견. 이 중 27건을 수정했고 3건은 앱에서 해결할 수 없는 항목으로 분류했습니다(6장 참조).

## 3. 테스트 시나리오와 발견된 문제

### 시나리오 1 — 앱을 처음 설치하고 가입한다

이메일로 가입을 시도했습니다.

**발견한 문제**

약관 화면에서 표시된 필수 항목을 모두 체크해도 '동의하기' 버튼이 회색으로 남아 **가입을 더 진행할 수 없었습니다.** 왜 안 되는지 화면에 표시되지 않아 원인을 알 수 없었습니다. '전체 약관동의'를 누르면 그때만 진행됐습니다.

비밀번호를 짧게 입력하면 가입 버튼은 활성화되는데, 누르면 "회원가입에 실패했습니다. 잠시 후 다시 시도해주세요"만 반복됐습니다. 몇 번을 다시 시도해도 결과가 같았습니다. 실제 원인은 서버의 최소 8자 규칙이었지만 그 내용이 사용자에게 전달되지 않았습니다.

가입할 때 성별을 반드시 고르게 하는데, 가입 후 내 정보를 보면 성별이 비어 있었습니다.

**조치**

화면에 존재하지 않는 숨은 동의 조건 두 개가 필수로 걸려 있어 발생한 문제였습니다. 앱이 사용하지 않는 조건이므로 제거하고, 화면에 보이는 항목만 필수로 두었습니다. 비밀번호는 입력 단계에서 길이를 확인해 안내하고, 서버가 알려주는 실패 사유를 사용자에게 그대로 전달하도록 고쳤습니다. 성별은 가입 직후 프로필에 저장되도록 연결했습니다.

> 빌드 2 (PR #19)

### 시나리오 2 — 약을 등록하고 알람을 기다린다

약 이름과 복용 요일, 시간을 입력해 등록했습니다.

**발견한 문제**

시간 추가 버튼을 두 번 누르면 같은 시각이 두 줄 생기고, 그대로 등록하면 **같은 약의 알림이 두 번 울렸습니다.** 시간을 지우려 하면 항상 마지막 줄만 지워져, 가운데 시간을 빼려면 뒤의 시간까지 지웠다가 다시 입력해야 했습니다.

입력을 마칠 즈음 화면 아래 탭 아이콘을 잘못 누르면 **확인 없이 화면이 바뀌고 입력한 내용이 전부 사라졌습니다.**

가장 심각했던 것은 반복 알람이었습니다. 매주 반복으로 등록한 알람이 **첫 번째 발생 이후로는 울리지 않았습니다.** 앱을 열면 다시 예약되지만, 알람만 받고 앱을 열지 않는 사용자에게는 알람이 멈춘 것과 같았습니다.

**조치**

시간 추가 시 중복이 생기지 않도록 바꾸고, 등록 직전에 한 번 더 중복을 정리해 서버 기록과 기기 알림이 어긋나지 않게 했습니다. 시간 줄마다 개별 삭제 버튼을 두었습니다. 입력 화면에서는 하단 탭바를 제거했습니다.

반복 알람은 특정 날짜를 고정해 예약하고 있어 그 날짜가 지나면 다음 발생 시점이 없어지는 구조였습니다. 요일 기반 반복으로 바꿔 매주 같은 요일에 울리도록 했습니다.

> 빌드 1 (PR #18), 빌드 3 (PR #20), 빌드 7 (PR #24)

### 시나리오 3 — 알람을 받고 복용을 기록한다

설정한 시각에 알람을 받은 뒤 복용 완료를 기록해 봤습니다.

**발견한 문제**

화면 잠금이 풀린 상태에서 알림을 누르면 **아무 일도 일어나지 않았습니다.** 앱이 열리지도, 복약 화면으로 이동하지도 않아 앱이 고장 난 것처럼 보였습니다.

전체화면 알람에서 '복용 완료'를 밀면 화면은 정상적으로 닫히는데, 나중에 캘린더를 보면 **미복용으로 남아 있었습니다.** 네트워크가 불안정하거나 서버가 요청을 거부한 경우인데, 실패했다는 사실이 전혀 표시되지 않았습니다. 홈 화면의 복용 완료도 마찬가지로 눌러도 아무 변화가 없었습니다.

복용 완료를 기록하려면 타일 구석의 작은 점 세 개 아이콘을 찾아 눌러야 했습니다. 복약 앱의 가장 중요한 동작이 가장 찾기 어려운 곳에 있었습니다.

알람이 울리는 바로 그 순간 해당 약이 이미 빨간색 '미복용'으로 표시됐습니다. 알람을 받고 앱을 열었을 뿐인데 이미 놓친 것으로 보여 부담스러웠습니다.

복용 완료를 누르기 전에 "오늘도 해내셨네요!" 축하 문구가 먼저 뜨고, 버튼은 '닫기'와 '확인'이었습니다. '닫기'를 누르면 기록이 남지 않는데 사용자는 이미 완료된 줄 알았습니다.

**조치**

알림을 누르면 복약 화면이 열리도록 했습니다. 복용 기록이 실패하면 화면을 닫지 않고 이유를 안내해 그 자리에서 다시 시도할 수 있게 했으며, 홈 화면도 같은 방식으로 고쳤습니다. 복용 완료 버튼을 타일 안에 직접 배치하고 터치 영역을 넓혔습니다. 미복용 판정에는 60분 유예를 두었고, 확인창 문구는 행동을 묻는 표현으로 바꿔 축하 메시지는 기록에 성공한 뒤에 보여주도록 했습니다.

> 빌드 3 (PR #20), 빌드 7 (PR #24)

### 시나리오 4 — 로그아웃했다가 다시 로그인한다

마이페이지에서 로그아웃한 뒤 같은 계정으로 다시 로그인했습니다.

**발견한 문제**

약 목록은 그대로 보이고 알람 스위치도 켜져 있는데, **알람이 한 번도 울리지 않았습니다.** 화면상으로는 아무 이상이 없어서 문제를 알아차리기 어려웠습니다. 기기를 바꾸거나 앱을 다시 설치한 경우에도 같은 증상이 나타났습니다.

**조치**

로그아웃 처리가 기기에 저장된 알람 데이터를 통째로 지우고 있었습니다. 예약된 알림만 취소하고 저장 데이터는 남기도록 바꿨습니다. 이메일 로그인 경로에만 빠져 있던 재예약 처리를 추가했고, 서버에 등록된 약 중 기기에 예약이 없는 항목은 목록을 불러올 때 자동으로 예약되도록 했습니다.

또한 앱을 완전히 종료한 뒤 새 약을 등록하면 **먼저 등록한 약의 알람이 사라지는** 문제도 함께 확인됐습니다. 알림 식별자가 앱을 켤 때마다 1번부터 다시 발급되면서 기존 알람을 덮어쓰고 있었습니다. 식별자를 기기에 저장하도록 바꿔 해결했습니다.

> 빌드 1 (PR #18)

### 시나리오 5 — 가족을 초대한다

가족 그룹을 만들고 전화번호로 여러 명을 초대했습니다.

**발견한 문제**

여러 명을 초대하다 한 명에게서 실패하면 "그룹 생성 또는 초대 전송에 실패했습니다"라는 한 줄만 표시됐습니다. 전부 실패한 줄 알고 처음부터 다시 시도하면, **같은 이름의 가족 그룹이 하나 더 생기고** 앞서 성공했던 사람에게 초대가 다시 갔습니다.

**조치**

성공과 실패를 각각 집계해 "3명 중 2명에게 초대를 보냈습니다"처럼 결과를 알려주도록 했습니다. 이미 만들어진 그룹은 재시도할 때 다시 사용하고, 성공한 대상은 목록에서 빼 실패한 사람에게만 다시 보낼 수 있게 했습니다.

> 빌드 4 (PR #21)

### 시나리오 6 — 마이페이지에서 설정을 확인한다

마이페이지 메뉴를 하나씩 눌러 봤습니다.

**발견한 문제**

'앱 정보'와 '사용자 의견 보내기'는 **눌러도 아무 반응이 없었습니다.** 메뉴는 보이는데 동작하지 않아 오류로 인식됐습니다.

로그인 과정을 살펴보던 중, 앱이 **로그인 토큰 전체를 기기 로그에 그대로 출력**하고 있는 것을 확인했습니다. 이 출력은 릴리즈 빌드에서도 제거되지 않아 토큰이 기기 로그에 남습니다.

로그인에 실패하면 원인과 무관하게 대부분 "잠시 후 다시 시도해주세요"로 표시됐습니다. 이메일 형식이 잘못된 경우처럼 다시 시도해도 소용없는 상황에서 잘못된 안내였습니다.

**조치**

'사용자 의견 보내기'를 의견 수집 설문 폼(`https://tally.so/r/zx9v5R`)으로 연결했고, '앱 정보'는 앱 이름과 버전을 보여주도록 했습니다. 외부 링크가 열리지 않을 때도 안내가 나가도록 했습니다.

토큰 출력은 완전히 제거했고, 통신 로그는 디버그 빌드에서만 출력되도록 제한했습니다. 로그인 실패는 비밀번호 불일치 / 이메일 형식 오류 / 서버 오류 / 네트워크 문제로 구분해 안내합니다.

> 빌드 5 (PR #22), 빌드 6 (PR #23)

- [ ] **minSdkVersion 확인 (기기 호환성 직결)** — `android/app/build.gradle.kts`는 `minSdk = 23`(Android 6.0)으로 선언돼 있으나, `flutter build`가 실행될 때마다 이 줄을 `flutter.minSdkVersion`으로 자동 변경하며 그 기본값은 **24**입니다. 실제 빌드된 AAB의 병합 매니페스트는 `minSdkVersion="24"`였습니다. **Android 6.0 기기는 설치 대상에서 제외됩니다.** 23을 지원할 의도였다면 Flutter 툴링이 덮어쓰지 않도록 값을 고정해야 하고, 24로 갈 의도였다면 소스의 선언을 24로 맞춰 실제와 일치시켜 주세요.
- [ ] **실기기 확인 — 주간 반복 알람** — 요일 기반 예약으로 변경했습니다. 실제 기기에서 다음 주 같은 요일에 재발화하는지 확인해 주세요.
- [ ] **실기기 확인 — 알림 탭 이동** — 잠금 해제 상태에서 알림을 눌렀을 때 복약 화면이 열리는지 확인해 주세요.
- [ ] **실기기 확인 — 큰 글꼴** — 시스템 글꼴 200% 배율에서 가입 화면 레이아웃을 확인해 주세요.
- [ ] **빌드 환경** — `android/app/build.gradle.kts`가 `key.properties`를 널 체크 없이 읽습니다. 이 파일이 없는 환경(CI, 신규 팀원)에서는 debug 빌드도 실패하므로 폴백 처리를 권장합니다.
- [ ] **FCM 토큰 로그** — `lib/services/notifications/fcm_service.dart`가 FCM 토큰을 `debugPrint`로 출력합니다. `debugPrint`는 릴리즈 빌드에서도 실행되므로 별도 정리가 필요합니다.
